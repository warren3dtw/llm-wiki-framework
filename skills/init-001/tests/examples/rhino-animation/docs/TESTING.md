# 驗收規範

| 結果 | 定義 |
|---|---|
| 通過 | 實際檢查符合 spec，有可追溯證據 |
| 失敗 | 已檢查，不符合 spec |
| 未執行 | 缺環境、資料或尚未檢查 |
| 不適用 | 此任務不需要；必須寫理由 |

每項任務檢查來源正確、規格逐項對應、產物存在且可開啟、未修改受保護來源、文件與成果版本一致。
記錄操作／命令、前置條件、來源版本、預期、實際與證據位置，寫入該計畫 tasks 的驗收表。
無證據不得通過，任務勾選不替代驗收。沒有環境時標未執行，不能編造測試命令。
選定技術後新增實際命令、依賴與預期結果；沒有測試不是通過。

## 動畫驗收

檢查排序核准證據、JSON 與 GLB 的 GUID 雙向對應、組內相對位置與最終姿態等於原模型、bounds 與單位方向、任意跳格同姿態、素材載入失敗會中止渲染、代表幀與短片，以及正式影片的 codec、尺寸、fps、幀數與時長。只讀程式不能宣稱畫面通過；build 產生的 bundle 不等於影片。

常見陷阱：漏查隱藏或鎖定物件；重疊或跨樓層 group 被自動合併；用累積 delta 或未固定亂數算動畫；JSON 與 GLB 混用修訂；審查用低精度網格被當成正式交換資料。
