# Hooks 啟用方式

此空結構預設未啟用 hook，settings 的 hooks 為空是有效狀態。
沿用 host 權限，不代表所有操作獲准；不更動全域設定、不停用 sandbox、不預先允許任意程式碼。
rules 是行為指示，不是強制攔截。

## 啟用流程

1. 連接實際工具、讀 schema，確認名稱、版本及副作用。
2. 確認 host 事件／參數、OS、shell 與執行環境。
3. 建立並檢查腳本，確認輸入／輸出及失敗行為，再合併 settings；不存在腳本不註冊。
4. 可執行程式碼、修改、寫檔及匯出工具要求權限確認；查詢只有確認無啟動／修改副作用才可預先允許。
5. 既有 settings 保留未知欄位及政策，陣列與 hooks 去重，衝突不自行放寬；平台能力按實際 host 查證。
6. 以模擬輸入實測後記入 docs/INIT-REPORT.md；未測不得聲稱啟用成功。

## 路徑與涵蓋範圍

交付保護從固定專案根目錄或腳本位置解析，不使用會隨 cd 改變的 cwd 當根目錄。
相對路徑基準需與工具一致，未確認就要求絕對路徑。
測試根目錄、子目錄、中文／空白路徑、新檔與既有檔。
只攔截 save_doc 無法涵蓋 run_command、腳本或 CADCraft 寫檔，須明示限制；其餘仍靠權限及工作流程檢查。

Compact 提醒讀既有規範，不另存公差副本。
格式化、測試與通知只有存在實際命令且需要時才啟用，不更動全域通知。
重跑不刪除／停用既有 hooks；有錯誤記錄並修復驗證。明確要求可執行 hook 時，實際交付腳本與模擬測試，不能只交本說明。
