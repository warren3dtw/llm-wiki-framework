# init-001 內容契約：rhino-cadcraft

由 [SKILL.md](../SKILL.md) 指過來。只有 rhino-cadcraft 模式要讀。共用的契約在 [contracts-common.md](contracts-common.md)。

## Phase 4：rhino-cadcraft 文件擴充

只有 rhino-cadcraft 建立本節文件。general 不建立模式專用文件，也不產生指向它們的連結；rhino-animation 不建立 DRAWING，MODELING 與 DELIVERY 改依 Phase 4B。

### docs/MODELING.md

寫明 Rhino 負責 3D 建立／修改與所需 2D 幾何整理；尺寸、公差、座標與策略讀 PROJECT，不自行選常見值。

操作順序：確認實例與文件 → 確認來源和規格 → 依變更等級決定備份（task 不備份，spec 變更前一次） → 按計畫修改 → 幾何與視覺驗證 → 保存工作檔（正式交付才建立新版本） → 記錄產物。階段結束或中途要停時，先存到 models/ 並確認磁碟檔案存在；未存的內容不算存檔點。從草圖開始時，先依 DRAWING 的 D1 貼進 Rhino 校正比例並確認立面與構件範圍，再建模。

圖層表初始無實際圖層，首個模型時定義用途、名稱、輸出／輔助屬性，建模元素依下節分層。封閉要求依用途決定，2D 線條或開放曲面不因非封閉自動失敗。草圖底圖放獨立圖層並鎖定；校正線與 pattern 檢查線放輔助圖層，不輸出；細則見 DRAWING 的 D1。

## 建模方法

預設依點→線→面→體建模；使用者另有指定才改用其他方法，並記入 PROJECT。

- 每層只由上一層建立，不跳層：先列關鍵點座標建點，由點建線，由線建面，由面接合成體。用途不需要實體時可停在面或線。
- 建模元素依點、線、面、體分層保留，不刪除；可關閉顯示，查詢時包含隱藏物件。
- 本方法不依賴任何 skill；rhino-001 只是已安裝時可用的輔助，未安裝不影響。

## 建模檢查

- 曲線超出範圍要延伸時，優先沿用同一方程式保持曲率連續；切線接法會造成曲率跳動與偏差。
- 曲梁體積檢查用四邊平均長度，不用頂面長度。
- 驗證數值超標時先查原因，分清是模型問題或公式問題，不放寬標準。
- 案例：Rhino 8.36 俯視疊圖時，低於草圖底圖高度的物件會被遮住，看起來像缺件；要用數值確認存在，不只看截圖。這是版本相關案例，其他版本需重新查證。

## MCP 操作

以下是原 Rhino MCP 介面的注意事項，使用前核對當前實作 schema／說明，差異記入 PROJECT，不假設所有 Rhino MCP 相同：

- save_doc 可直接覆寫，交付使用新版本檔名。
- close_doc 不帶 path、close_slot 可能丟棄未存內容，關閉前驗證已存。
- open_doc 可能是匯入；clearFirst 可能清空物件，不把它當唯讀開檔。
- 明確定位 slot；先用不啟動實例的狀態工具查詢，不關閉使用者管理的實例。
- run_command 前查可用指令及參數，使用 filter 避免無限制列表。
- 修改前取 context，修改後列物件及查看視圖；隱藏物件納入對應檢查。
- ask_user 若非同步，呼叫成功不表示收到答案；等待真正答覆才做依賴操作。
- 腳本使用 MCP 實作提供的文件參照（原介面為 __rhino_doc__），不猜測作用中的文件。
- 視圖截圖可能超過工具回傳上限，圖片改存到工具結果檔。先依當前實作與 host 確認回傳方式；有存檔時從存檔解出圖片再檢視，不因回傳沒有圖片就判定截圖失敗；取不到圖片時視覺驗證標未執行。
- 案例：Rhino 8.36 的 get_viewport_image（MCP 實作版本未記錄）以 1280×720、800×720 都超過上限，結果存成 JSON 檔，解出 JPG 後檢視；這是版本相關案例，其他版本需重新查證。

將以上建模方法、建模檢查與 MCP 注意事項寫入 MODELING.md；案例只記版本，不作全域預設。

### docs/DRAWING.md

寫入完整流程：

1. 判斷輸入為草圖、Rhino 3D 或既有 2D，在 specs 記來源版本；草圖先完成下表 D1。
2. 從 3D 取得 2D 前確認視圖、投影／剖面、比例、座標與圖層映射，再產生工作 DWG。視圖方向與投影做法見下方。
3. 明定可重產幾何與需保留的人工標註／排版，不直接覆寫已編修 DWG。3D 更新後比對差異並重驗受影響圖面。
4. CADCraft 讀工作副本；確認 DWG 版本、單位、字型、外部參考、標註樣式及圖層。
5. 按 PROJECT 設定 Layout、紙張、方向、視口比例、CTB／STB、線寬與色彩，不預設所有專案 A1 或黑白。
6. 正常保存工作 DWG（task 不另存備份），正式交付時才使用新版本；重開 DWG，確認文字、標註、圖層、版面持續正確。
7. 由 CADCraft 輸出新版本 PDF，依 TESTING 逐頁驗證，交付見 DELIVERY。

沒有 CADCraft 工具時，提供明確人工步驟與待驗收項目，不虛構 MCP 名稱或宣稱已出圖。案例經驗附版本與來源，不將特定字高、DIMSCALE、字型當全域規範。

## 全流程階段

從草圖到 PDF 分成下列階段，每階段依 DEVELOPMENT 的「階段存檔與續作」保存。用不到的階段在 tasks 標不適用並寫原因，例如 2D-only 的 D1、D2。

| 階段 | 工作 | 存檔位置 | 完成條件 |
|---|---|---|---|
| D1 草圖 | 草圖放入 sources/ 後不修改；貼進 Rhino 校正比例，列出尺寸、單位與假設，確認立面與構件範圍，找出 pattern 規則；細則見下方「D1 草圖判讀」 | sources/（原圖）；models/ 的 .3dm（校正與檢查線）；判讀結果寫 specs | 比例與 pattern 殘差有數值證據；尺寸、單位、公差、未標註值、立面型式、構件範圍及判斷不了的項目經使用者確認 |
| D2 3D 模型 | 依 MODELING 在 Rhino 建模，建模元素留在圖層 | models/ 的 .3dm | 已存檔且磁碟檔案確認存在，幾何與尺寸檢查有證據 |
| D3 2D 圖面 | 由模型投影取得視圖或剖面，不手描，產生工作 DWG | drawings/ 的 .dwg | 線數與投影核對相符；重開 DWG，圖層、比例與線條正確 |
| D4 排版 | CADCraft 設定 Layout、標註、字型與樣式 | 同一份工作 DWG | 視埠比例實算相符；存檔重開後文字、標註與版面仍正確 |
| D5 PDF | CADCraft 由 Layout 正式出圖 | deliverables/ 的新版本 PDF | 直接解析與渲染 PDF 並整頁目視，依 TESTING 驗證 |
| D6 審查交付 | 記入 DELIVERY 與 FEATURES，交使用者審查 | DELIVERY、FEATURES | 使用者接受；在此之前維持待審查 |

草圖的判讀值未經確認前不是規格，不得據以建模。

### D1 草圖判讀

適用所有從草圖開始的任務；實際數值與容許殘差寫在該專案的 specs，不寫進本規範。

1. **貼進 Rhino 校正比例**：草圖一定要貼進 Rhino，用圖上尺寸找到正確的圖片比例，不憑目測或假設比例。以多組標註總長分別反算，不同方向都要取，比較各組結果以驗證標註單位及圖片是否變形；再依標註重建軸線疊回草圖，逐條記殘差。殘差超過 specs 的容許值時先查原因，不硬調。校正後草圖圖層鎖定；校正只動 Rhino 內的圖框，sources/ 的原圖不改。標註總長不足以互相比對時，列待確認請使用者提供依據。
2. **尺寸互相驗證**：分段尺寸加總與總長互相驗證。被遮住、難辨識或由加總、量測推得的值標明「推得」，請使用者確認。
3. **立面向使用者確認**：立面是斜率還是曲率一律問使用者，不從線條自行判定，未確認不建模。答案是曲率時，一併確認定義，例如方向、半徑或矢高。
4. **找 pattern，不逐線描**：草圖線條通常潦草，不要逐線描。有 pattern 的圖面找出相同邏輯與關聯，例如間距、對稱、重複單元、尺寸之間的加總或倍數；寫成規則，依規則重建線條疊回草圖，以數值比對殘差，區分設計意圖與手繪誤差。判斷不了的請使用者決定，不自行取捨。沒有 pattern 的部分依標註重建，沒有標註的列待確認。
5. **構件範圍向使用者確認**：構件範圍不屬於可代為決定的選項，使用者授權「其他選項你處理」也不包含增減構件。圖上有規律但歸屬不確定的構件要列出來請使用者確認，未確認前不自行納入或排除。

校正線與檢查線是判讀工具，不是模型；D2 只採用已確認的規格。Rhino 未連線時可先列尺寸與假設，比例校正與疊圖比對標未執行，D1 不算完成。

## 參考圖與視圖方向

參考圖只取表達方式，例如圖面組成與標註習慣；幾何以確認的模型為準，不把參考圖當規格，也不為配合參考圖改模型。差異列給使用者，圖上只畫模型有的內容。

視圖方向以能呈現模型特徵為準，不照參考圖的圖名或方向；例如曲率要從看得到曲線的方向表達。不確定就問使用者。

## 3D 轉 2D 與出圖檢查

- 2D 由模型投影產生，不手描；匯出後核對線數與投影相符，不符先查原因。
- 標註與排版在 CADCraft 進行。
- Layout 視埠比例由 viewHeight 除以 height 實算，單位不同先換算，不只看設定值；欄位名稱依當前工具輸出。
- 分批呼叫 CLI 時注意指令長度上限，每批先恢復目前圖層與樣式。
- 生成圖層名稱交付前改正式名稱，對應見 PROJECT。
- 案例：Rhino 8.36 的 HiddenLineDrawing 可投影實體；這是版本相關案例，其他版本需重新查證。
- 案例：CADCraft CLI 0.17.0 的 mleader 在 PDF 未見文字，原因未確認，改用線加文字；這是版本相關案例，其他版本需重新查證。

## 出圖入口與實測依據

先分辨模型空間預覽與 Layout 正式出圖。一般 export／convert 可能只產出 model space，不因副檔名為 PDF 就視為正式圖紙。
先查目前工具 schema／命令目錄，再選明確支援 Layout 的出圖命令；記錄 layout、紙張、方向、比例及樣式。
案例：CADCraft CLI 0.17.0 曾以 plot 指定 Layout1 正式出圖；這是版本相關案例，其他版本需重新查證。
軟體在執行不等於 AI 工具已連線。MCP 不可用時先盤點已安裝且有說明的 CLI；有安全的 headless 入口可使用，不操作使用者目前開啟文件。
應直接解析與渲染輸出 PDF，並整頁目視；另存 PNG 只作輔助，不能取代 PDF 本身驗收。


將以上全流程階段、參考圖與視圖方向、3D 轉 2D 與出圖檢查、出圖區分與能力盤點寫入 DRAWING.md；實測版本僅為案例，不作安裝先決條件。

### docs/DELIVERY.md

初始交付清單為空。每次交付記：成果 ID、來源 3dm／2D 版本、工作 DWG、PDF、設定摘要、日期、驗收結果、驗收人／角色、已知限制。2D-only 的 3dm 欄標不適用。

規則：來源唯讀；工作檔與交付分離；既有交付不可覆寫；寫入前檢查版本未使用；最高版本不等於核准版。多檔交付需配套一致，不混用修訂。

PDF 驗收至少含可開啟、頁數、頁序、尺寸、方向、比例、裁切／重疊、缺字、線寬及色彩。依要求安排自動與人工檢視；待人工確認保留待審查。
