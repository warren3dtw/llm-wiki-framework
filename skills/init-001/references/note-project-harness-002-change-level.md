# 變更等級：在規格內的修改不備份，改規格前備份一次

- 代號：agent:note/project-harness-002-change-level
- 類型：筆記・規則
- 摘要：task 等級直接改、不備份；spec 等級先更新規格，第一次實際變更前備份受影響的工作檔一次
- 出處：Rhino-init 工作專案快照（2026-11-14），init.md 規格 2.2 「變更等級與備份」
- 狀態：草稿，還沒有經過作者確認

每改一次就備份一次，會產生大量沒人看的副本，也分不清哪一份才是現行的。所以先判斷這次修改是不是改了規格。

## 規則

- **task 等級**：在已經確認的規格範圍內完成任務、修正錯誤、微調。直接改工作檔並正常存檔，不備份。
- **spec 等級**：改了已確認的需求、尺寸、單位、公差、範圍或驗收條件。先更新規格並記下影響，再在第一次實際變更前，備份受影響的工作檔一次；同一批規格變更底下的任務不再重複備份。
- 判斷看實質內容：任務標了規格編號、改了勾選或文字，不會自動變成 spec 等級。
- 正式交付用新的版本號，不覆寫已經發布的成果。這是交付版本，不是作業前的備份。
- 每次修改都記在問題與調整紀錄：等級、理由、有沒有備份、驗證結果。

## 成立條件

有工作檔（模型、圖面、程式）而且需要能回到修改前的狀態。

## 不適用的情況

全部檔案都在 git 裡、每次修改都會 commit 的情況：git 本身就是備份，只需要照規格的變動判斷要不要重做驗收。
