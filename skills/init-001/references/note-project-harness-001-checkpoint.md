# 階段存檔點：每個階段結束或中途要停時，都要留下可以接續的狀態

- 代號：agent:note/project-harness-001-checkpoint
- 類型：筆記・規則
- 摘要：存檔點四項缺一不可：產物已存、確認存在並記錄識別碼、記下輸入和工具的版本、寫下一步
- 出處：Rhino-init 工作專案快照（2026-11-14），init.md 規格 2.2 「階段存檔與續作」
- 狀態：草稿，還沒有經過作者確認

工作常常跨好幾次對話。下一次接手的人或 agent 只看得到檔案，看不到上一次的對話，所以進度要寫在一個固定的地方：計畫的「階段與存檔點」表，它是進度的唯一來源。

## 規則

- 存檔點四項缺一不可：
  1. 產物已經存到專案裡。軟體裡沒存的內容不算。
  2. 確認檔案真的在，並記下識別碼：工作檔記雜湊值；在 git 裡的檔案記 commit。
  3. 記下輸入的來源版本和工具版本。
  4. 寫下一步：做到哪裡、接下來做什麼。
- 中途要停時一樣先存檔，階段維持「進行中」。
- 狀態只用：未開始、進行中、已存檔、已驗收、需重驗、不適用。
- 上游的產物改了，下游已驗收的階段改成「需重驗」，舊的驗收不沿用。
- 續作時先核對識別碼和檔案一致，再從第一個不是「已驗收」的階段繼續，不重做已驗收的。
- 存檔點不是備份，不為了存檔另外複製檔案。

## 成立條件

工作分成好幾個階段，可能中斷或換人接手。

## 不適用的情況

一次對話內就能做完、沒有中間產物的小修改。
